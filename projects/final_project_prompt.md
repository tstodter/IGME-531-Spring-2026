# Project 3: Freeform

In this project, you will create a computational artwork of your own design, drawing on the techniques and ideas we have explored throughout the semester. The subject, the medium, and the scope are up to you, provided that the output is significantly produced by a program you have written.

This is an opportunity to pull together what you have learned and make something that reflects your own aesthetic. You may build on earlier work from this class, combine multiple techniques, or strike out into territory we did not cover together. The only hard requirement is that code must do the generative work — your program should be the thing shaping the final piece, not a convenience around manual design.

Your piece should feel intentional. Consider composition, restraint, timing, color, and form with the same care you would give any other artistic medium. A small, well-considered piece using a single technique will be better received than a sprawling demo that touches every topic of the semester.

### Project Steps:

1. **Concept and Scope:**
   - Decide what you want to make and commit to a direction early. Freeform projects fail more often from drifting between ideas than from picking the "wrong" one.
   - Identify which technique(s) from the semester (or outside it) will serve as your primary tools. Examples: L-systems, cellular automata, reaction-diffusion, 3D L-systems, SDF fragment shaders, pattern-based music via Strudel, or combinations thereof.

2. **Research and Inspiration:**
   - Identify one or more artists, works, or references that inform your piece. These can be from inside computational art or far outside it.
   - Credit these sources in your reflective writeup.

3. **Implementation:**
   - Build your piece. Expect to iterate. Early prototypes that look crude are normal — the aesthetic work happens in revision.
   - Keep the code readable enough that you can explain it during critique.

4. **Reflective Analysis:**
   - Once the piece is complete, reflect on the process. What did you intend? What did the material push back on? What changed between your first sketch and the final version? What did you learn that you didn't know at the start?

### Objectives:

This project aims to:
- Give you space to practice artistic decision-making in a computational medium.
- Demonstrate your ability to combine technique with aesthetic intent.
- Build something you are willing to show publicly and discuss in a critique.
- Produce a piece you can add to a portfolio or reference in future work.

### Requirements:

- The output must be significantly generated by code you have written. You may reuse code from earlier in the semester, but the final piece should be distinct from prior assignments.
- The piece should be presentable. If it is visual, it should run (or export a still) on any reasonable machine. If it is audio, provide a recording and the source pattern. If it is physical (plotted or printed), bring it to class.
- Scope should reflect the time available: roughly one week of focused work. This should be a larger undertaking than any single weekly assignment.

### Submission Requirements:

For project submission, please include:
- The source code (single file, folder, GitHub link, or Strudel REPL link — whatever is appropriate for the medium).
- A viewable artifact: a running link, a short video, a still image, or the physical object for plotted/printed work.
- Succinct documentation of the program, including how to run it and any parameters that can be adjusted.
- A short written reflection addressing the questions above (concept, research, process, what you learned). A paragraph or two per question is sufficient.
